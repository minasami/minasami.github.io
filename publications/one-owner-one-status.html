One owner, one status, one clock: a file rule for clinical requests

Mina Sami Tawfik Saad, licensed pharmacist, Cairo

A clinical request fails when the evidence, the owner and the next date live in different chats. The rule I use is small: one object, one owner, one status, one clock.

Decision sentence. The file is complete or it is not. If it is not, the missing item, the owner and the date are written in the same note.

What goes in the note

  • What was asked, and which evidence is already in the pack.
  • Whether the documented condition supports the request. On an in-house EMR this includes the ICD-10 line matching the note, not the other way around.
  • The decision: proceed, query, or stop, with a reason a counterpart can read without a meeting.
  • Who owns the next move, and the date it is due.

Where I have used it

At EVA Pharma I use this rule on medicines files and on Doctor Portal, the in-house EMR: team adoption, test and debug, and a written workflow for the digital team. Independently, Medicine Support Hub (medicinesupport.app) keeps a request to the same four fields.
